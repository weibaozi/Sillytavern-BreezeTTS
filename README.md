# SillyTavern Breeze 角色语音 · 0.7.0-tag-render.4（实验分支）

模型只写一份 `[TTSVoice:角色名:情绪:对白]`，插件在显示层把它呈现为普通引号对白和播放气泡。原始聊天 `mes` 保持不变，已绑定角色连接原 Breeze WebUI 合成及播放；未绑定角色仍显示对白，仅跳过语音。原有独立工作室、音色库、流式播放、语气词设置和共享语料库保留。

当前开发分支为 `experiment/ttsvoice-render`。稳定分支 `stable/v0.6.1` 与标签 `v0.6.1` 保留在基线提交 `60df1f8`。本地酒馆已试用前一版单份对白插件，本次更新后刷新页面生效。实现范围、历史兼容边界及回退方法见 [单份对白方案](docs/单份对白方案.md)。

- **稳定插件**：`G:\study\AI\breeze-tts\sillytavern-breeze`，保留 0.6.1。
- **实验插件**：本目录 `G:\study\AI\breeze-tts\sillytavern-breeze\branches\ttsvoice-render`，打开这里的 `酒馆插件.code-workspace`。`extension/` 是可安装扩展，无运行时 npm 依赖。原有酒馆预设、世界书、参考和实验文件保留；迁移清单为 `relocated-files.json`。
- 音色和合成文件保存在原 TTS 的 `data/tts/`，不放入插件。映射和音频缓存引用存于酒馆当前聊天的 metadata。

## 实验安装与首次使用

按以下步骤安装或更新同名扩展，**不要把稳定版和实验版作为两个扩展同时安装或启用**；两者使用同一个提示词 key、设置命名空间和聊天事件。

1. 使用已有配套 Breeze WebUI 并加载模型；从 0.6.1 试用本实验无需更改或重启后端。首次部署仍需支持 `/breeze/*` 的配套后端。
2. 在本实验目录执行安装脚本；需要显式添加 `-InstallExperimental`。脚本先备份当前同名扩展，再替换到：

   ```text
   G:\study\AI\SillyTavern-Launcher\SillyTavern\data\default-user\extensions\sillytavern-breeze\
   ```

   目录下应直接包含 `manifest.json`、`index.js`、`dialogue-render.js`、`automatic-queue.js`、`panel.js`、`panel.css`、`stream-player.js`、`extra-prompts.js` 等文件。其他酒馆用户使用其自己的用户目录，可通过 `-UserHandle` 指定。实验包为 `dist/sillytavern-breeze-0.7.0-tag-render.4.zip`。

   ```powershell
   .\install.ps1 -SillyTavernPath 'G:\study\AI\SillyTavern-Launcher\SillyTavern' -InstallExperimental
   ```

3. 刷新酒馆页面，点击输入栏左下方的 **魔棒 → Breeze 语音工作室**。在「连接与播放」填写地址，默认为 `http://127.0.0.1:7860`，点击「保存并连接」。
4. 在「本地音色库」展开「导入参考音色」直接保存已有音频和准确文字。需要创造新声音时，在「声音设计室」选择「文字设计」或「语音方向」：前者填写描述，后者上传参考音频与准确文字（可试听上传的参考，声音描述可留空），再填写试听文本和候选数量，生成、试听后命名保存。
5. 打开一个聊天，在「角色与音色」给角色选择音色，可以搜索角色并直接试听已绑定声音。初始映射为空，未映射角色跳过；多个角色可以共用同一个音色。
6. 先点击已有对白气泡试听，再按需要打开「自动生成」或「自动播放」。两者默认关闭；自动播放开启时会同时生成。若要在模型输出过程中开始处理完整对白，再打开「读取流式文本」；加载历史不会自动朗读。

7. 「预设注入」默认开启。插件在每轮生成前通过酒馆 `setExtensionPrompt` 注入英文 TTSVoice 规范，自动填入当前聊天角色、已绑定／未绑定名单与当前语气词列表。默认四个语气词，可直接在面板编辑；额外语料可命名保存，再由各聊天选择和启用。无需再手动复制整段输出规范。

试用时关闭手工重复添加的 **TTS 输出规范条目**。若使用本项目旧的 TGbreak 兼容片段，应将其中“正文对白后再追加副本”改为新片段 [TGbreak 单份对白实验版](prompts/TGbreak_原思维-格式_单份对白实验版.txt)；仅调整 TTS 要求，保留原剧情、格式、咪咪吐槽等约束。插件不会自动修改已保存的预设文件、提示词顺序或历史消息。

### 单份对白显示

模型原始回复示例：

```text
周启明拍了拍肚子。
[TTSVoice:周启明:happy:[笑]一起去食堂？]
```

显示为普通旁白、“一起去食堂？”和播放气泡。对白使用酒馆原生 `q` 引号样式，跟随主题的 `--SmartThemeQuoteColor`，默认橘黄色。角色名、情绪、外层标记不混入正文。仅在显示时去掉当前配置的发声标签和历史默认四项 `[笑]`、`[叹气]`、`[咳嗽]`、`[清嗓子]`；未知方括号内容保留，送入 TTS 的文本保留原发声标签。未绑定角色仍能读到完整对白。

旧的“引号对白＋紧邻 TTS 副本”采用保守兼容：只有紧邻段落内引号对白的完整内容与标签对白匹配时，才只显示气泡以避免重复。此匹配不是语义识别；文字改写、额外空行等复杂格式可能仍显示两份。原始消息不被去重或改写。

### 读取流式文本

「连接与播放」新增「读取流式文本」（默认关闭）。开启后，外层 `]` 闭合的完整 TTSVoice 会按「自动生成／自动播放」设置追加到顺序队列，无需等模型整条回复结束，也不会打断当前句。两项自动开关都关闭时，仅渲染并提供手动播放。

开启「显示为对白与气泡」时，正在输出的标签会实时隐藏角色、情绪等元数据，并逐步显示已经到达的对白；标签不完整时不提交语音。关闭「读取流式文本」仍实时渲染，但自动语音等整条回复完成后才处理。停止、编辑、切换 swipe 或聊天会取消旧队列；代码块、编辑器和原始消息保持原样。

### 流式生成与播放

在「连接与播放」开启「流式生成与播放」（默认关闭）。点击对白气泡、播放本条或自动播放时，新的合成任务会边生成边传输音频；浏览器收到首段即可开始播放。当前句播放完再进入下一句，暂停、继续、音量及停止仍可使用。

生成完成后保留完整 WAV 和原有聊天缓存引用，下次点击直接重播；仅预生成时仍使用完整音频流程。切换聊天、修改消息或停止会中止流式播放并取消未完成任务，未完成音频不写入聊天缓存。后端仍按原队列串行推理。

首次升级到支持音频流式的 Breeze 后端需要重启；本次插件更新无需重启已有配套后端。不支持流式的旧后端会提示更新或关闭该开关。浏览器自动播放权限仍适用，首次可能需要手动点击一次气泡。此开关控制 TTS 音频传输，与「读取流式文本」独立，可按需组合开启。

### 预设注入设置

- 支持独立开关、英文模板编辑、保存、恢复默认。预览以已保存模板为基础，随语气词列表和当前聊天语料实时更新；这两栏自动保存，英文模板本身仍使用「保存模板」。禁用整个插件也会清除其注入。
- 默认以系统角色注入到聊天深度 **1**，即最近一条聊天之前；可改成 0–100。深度 0 更靠近聊天末尾，但不保证比预设里所有其他指令更靠后，也不能保证模型完全遵循格式。
- 普通生成、重生成、swipe、续写和普通提示词预览使用规则；后台 `quiet` 生成（例如摘要）及 `impersonate` 用户代写跳过规则。切换聊天、映射、角色及预设后重新注册，避免残留旧名单。
- 未绑定角色仍输出 `New` 标记，以便发现新角色；播放时跳过。注入中的角色名保持剧情人物名，不用音色库名字替代。
- 内置插槽：`{{primary_character_note}}`、`{{bound_characters_section}}`、`{{skipped_characters_section}}`、`{{unbound_characters_section}}`、`{{vocal_events}}`、`{{vocal_event_example}}`、`{{user}}`。当前跳过名单只包含用户；其他酒馆宏由酒馆发送时处理。预览不是最终完整请求。
- **语气词列表**：所有聊天共用，默认 `[笑]`、`[叹气]`、`[咳嗽]`、`[清嗓子]`。每行一项，也支持中英文逗号、顿号或分号；可省略外层方括号，自动去重。格式无效的项会提示并跳过。清空表示不添加语气词，可一键恢复四项。规则和示例通过上述两个语气词插槽同步更新。
- **额外语料库**：点击「新建并使用」，填写名称与背景、情绪或发声指导；名称在编辑结束时自动保存，内容输入时自动保存并更新预览。名称不可为空或重复。其他聊天直接在下拉框选择已有语料，并开启「在当前聊天启用」即可复用。
- **聊天绑定**：语料库保存在酒馆插件全局设置，每个聊天只保存所选语料的稳定 ID 和启用状态。修改共享内容会影响所有选用它的聊天；需要单独调整时用「复制并使用」。改名不会破坏绑定。关闭开关或选择「不使用语料」保留库中内容；删除需确认，其他聊天的失效绑定不再注入。
- **注入与迁移**：只有当前聊天启用、选中有效语料且内容非空时，才在编译预设末尾追加 `6. Additional scene guidance (current chat):` 和正文。0.5.0 的旧语料在打开对应聊天时自动命名、存入库并绑定，保留原开关及旧文字备份，不反复创建；删除或取消绑定不会重新启用旧备份。
- 实验模板单独保存到 `tagRenderPromptTemplate`，稳定版的 `settings.promptTemplate` 原样保留，方便回退。实验首次使用单份对白默认模板；在此分支保存或恢复模板不会覆盖稳定版模板。语气词列表、语料库、聊天绑定及其他原有设置继续共用。
- 单份对白模板保留五条规则；启用有效、非空的聊天语料时追加第六条。自定义模板需包含 `{{vocal_events}}` 才能同步列表，可用 `{{vocal_event_example}}` 避免示例仍固定使用旧标签。多组语气词预设的管理与切换仍留作后续。
- 英文规则要求所有实际发言在标签内仅出现一次，旁白和动作在外，覆盖短句、问句及最后两次发言；这些提示词不能保证模型每次完全遵循。旧的 0.6.1 双份规则保留为历史版本，不与实验规则同时使用。

机制参考 [EchoCore 的提示词注入器](https://github.com/haide-D/SillyTavern-EchoCore/blob/main/frontend/js/prompt_injector.js)，实际参数及生成事件按本机酒馆源码校验。原手工模板保留在 `prompts/` 供对照。


## 旁白朗读

在「角色与音色 → 旁白声音」为当前聊天选择本地音色，情绪默认「平稳口气，配音」，可填写简短发声要求。音色和情绪随聊天保存；选择「不朗读旁白」关闭，音色失效也会跳过。旁白不加入角色名单或注入预设，不需要模型输出新标签。

消息底部「播放本条」和「自动播放全文」按原文顺序穿插旁白及已绑定角色对白；单个对白气泡仍只播放该句。仅开启自动生成时也会准备旁白音频，已有缓存继续复用。旁白正文外观保持原样，只有旁白的消息也可整条播放。

旁白从正文文字提取，排除 TTSVoice、引号内台词、代码、图片、正文前后模块及咪咪吐槽、摘要等，不会把历史双份对白的引号副本再当旁白读出。流式读取等完整句、换行或明确的对白边界再入队，结束时补读尾句；停止、切换聊天或修改旁白设置会取消旧队列。续写自动播放只读新增部分。

提取依赖文本结构，不识别所有自定义正则和 CSS 隐藏规则；自定义正文外模块需另行接入排除列表。没有 TTS 标签的引号对白继续跳过，不猜测说话人。

## 已实现

- 魔棒菜单入口与独立工作室：角色、音色库、声音设计、预设、连接五页；桌面和手机布局，样式通过 Shadow DOM 隔离，Esc 关闭并返回入口焦点。切页和关闭时暂停试听。
- 角色卡、群聊成员、历史 TTS 标签及手动角色汇总；映射按聊天隔离。
- 自动注入可编辑的英文 TTSVoice 规范、角色插槽及注入预览；保留 TGbreak 的其他模块。
- 嵌套方括号解析；语气词原样送入 TTS，不限死四项。排除用户、代码、w2g、catsay、摘要等内容；格式异常跳过并提示。
- 原标签位置显示引号对白和气泡；由 `dialogue-render.js` 提供显示文本与历史双份匹配，原始消息保持不变。其他正则改变显示导致定位失败时，使用消息下方的语音条。
- 单句播放、暂停／继续、整条播放、音频缓存和顺序播放；普通模式播放上一句时可准备下一句，流式模式按句边生成边播放。右键气泡清除该句缓存引用，下一次点击重新生成。
- 切换聊天、编辑、切换 swipe、重新生成和停止时中止旧播放，旧请求的结果不会回填到新消息。
- 参考音色上传、列表和试听；文字设计或参考音频方向均支持 1–8 个不同种子的候选，逐个生成、试听和保存。参考方向每个候选独立提交音频与准确文字，保存的参考文字来自被选候选的生成文本，不是上传参考的文字。
- WebUI「合成 → 已保存音色」可以读取同一音色库；也可在 WebUI 生成试听后创建音色，或在「音色库」直接导入参考。酒馆刷新音色库后可立即绑定。

## 使用边界

- 浏览器可能阻止自动播放，按气泡提示点击播放即可。没有标签的漏标对白不会被猜测补齐。
- 第一次连接需先加载模型；远程浏览器使用 TTS 电脑的实际地址，并用 `BREEZE_TTS_ORIGINS` 允许酒馆页面的 Origin。HTTPS 页面连接 HTTP 服务可能被浏览器阻止。
- 取消后立即停止播放；流式推理在后续分块处退出，普通推理结束后丢弃结果。单个任务等待上限 10 分钟。
- WAV 会持续保留。需要清理时先关闭 TTS，再清理 `data/tts/jobs` 的旧任务音频及配套 JSON；保留 `voices` 音色库。气泡缓存失效后可右键重新生成。
- WebUI 和独立 API 二选一运行；不要同时让两个进程使用同一套 `BREEZE_VOICE_DATA`。若确需多实例，应分别指定存储目录。
- 消息内新角色「就地绑定／跳过」和可配置语气词预设组仍在计划中。自动 prompt 注入已实现。
